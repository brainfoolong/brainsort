# The counted numbers are the same on every compiler and CPU

## Context

The test suite holds every algorithm to `results/counts.csv`, and the
website leads with these numbers because they do not depend on the machine.
The first CI run on other compilers and CPUs showed three ways in which they
did:

- Trace hashes of the timsort and pdqsort ports and of brainsort's
  displaced-element route differed between GCC on x86-64 and Clang or GCC on
  ARM64. The hash records the order of element reads, and expressions such
  as `less(get(i), get(j))` read in whatever order the compiler evaluates
  function arguments (GCC on x86-64 goes right to left, Clang and GCC on
  ARM64 left to right).
- brainsort's compressed radix plan (`PEXT`) was only considered when the
  CPU reports BMI2, so on ARM64 the sparse-bit and lowercase-string inputs
  took a different plan with more passes and larger tables.
- The double keys come out of `uniform_real_distribution`, whose `a*b+c` GCC
  contracts into a fused multiply-add on ARM64. The keys rounded differently,
  and so did the histogram buckets and the cache-model misses.

## Decision

- **One read order.** Wherever two hooked reads sit in one expression they
  are hoisted into locals, read left to right. The numbers are then a
  function of the source, not of the compiler.
- **The counted path considers `PEXT` on every CPU** and runs a portable
  bit-by-bit PEXT there; the timed path is unchanged and still uses the
  instruction only when the CPU has it. The counted numbers describe the
  algorithm as it runs on a BMI2 machine, which the timing pages on the
  website are measured on as well.
- **No floating-point contraction** (`-ffp-contract=off` on GCC and Clang;
  MSVC does not contract under its default `/fp:precise`). The library itself
  has no floating-point arithmetic, so only the benchmark's data generation
  is affected.

## Consequences

- `results/counts.csv` was regenerated: the trace hashes of the affected
  cells changed, nothing else.
- ARM64 CI holds the same golden file as x86-64. A cell that differs there is
  a real portability bug, not noise.
- On a CPU without BMI2 the counted path is slower than the timed path would
  be there; nothing on the website is measured through the counted path.
