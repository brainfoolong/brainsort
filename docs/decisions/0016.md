# The CI builds the Rust tests without debug info and tests the variants on Linux

## Context

The first CI run after the key inference, the keys-only routes and the
tests beyond the contract (decisions 0012 to 0015) lost every Linux job
that built the Rust tests: the runner reported a shutdown signal in the
middle of `cargo test`, before a test had run. The Windows jobs survived
but took three times longer than before, and the macOS job was still
compiling after twenty minutes.

Measured on the workstation, the compile of the api test binary alone,
`cargo test --no-run --test api` with every feature:

| test profile debug | rustc peak memory | wall time, 16 cores |
|---|---|---|
| 2 (the default) | 19.7 GB | 232 s |
| line-tables-only | 11.7 GB | 168 s |
| 0 | 7.9 GB | 113 s |

`-Z time-passes` puts 200 of the 240 seconds in LLVM and the memory in
the IR: the test instantiates every route of the sort for some forty key
types, in the by-reference and by-value projection forms, and each
instantiation carries the vector kernels, the scatter, the run merge and
the index route. A GitHub runner has 16 GB, so the Linux runners were
killed while compiling; Windows paged. The other four test binaries take
20 to 35 seconds each and the tests themselves run in under a minute.

The test job also compiled the bench crate and its three radix sort
dependencies in the test profile, for a crate that has no tests, and ran
four full rebuilds on every platform (every feature, no default features,
the scalar code, compile-time AVX2), each a new copy of the api test.
Separately, the C++ platform jobs found cargo on the runners and ran the
Rust API benchmark after their own, so four machine ids were measured
twice and uploaded under the same file name, and two ids (Clang, MinGW)
were measured under names the website cannot pair with a C++ file.

## Decision

- **`profile.test` has `debug = 0`** in the workspace `Cargo.toml`, for
  every `cargo test`, not only the CI's: a 16 GB laptop would be killed
  the same way. A failing assertion still names its file and line, the
  panic location is compiled in; only a debugger loses the source view,
  and a developer who needs it can pass `CARGO_PROFILE_TEST_DEBUG=2`.
- **The variants run on the Linux runners only.** No default features,
  the scalar code and compile-time AVX2 exercise library code, not the
  operating system, and the Linux runners compile three times faster
  than the Windows ones. macOS and Windows run the all-features build,
  and without the doc-tests, which are seven examples that the Linux
  jobs run. The ten-million-element test stays on Linux x86-64 stable.
- **The test job tests the library crate only** (`-p brainsort`); the
  bench crate is built, in release, by the golden and benchmark jobs and
  checked by clippy with every target.
- **The Rust port is measured once per machine id**, by the benchmark
  job of `rust.yml`; the C++ platform jobs set `BENCH_NO_RUST`.

## Consequences

- The Linux test jobs fit in memory again. Their compile time and the
  Windows one halve; the Windows jobs, the longest of the run, lose
  three of their four rebuilds.
- Line numbers inside library frames are gone from a test's backtrace;
  the assertion messages carry the key type, pattern, size and seed, which
  is what a failure needs.
- A platform-specific regression in the scalar or no-default-features
  build of the Windows or macOS targets would only show in the
  all-features build of that platform. The code those variants remove is
  `std` and the x86 kernels, neither of which the operating system
  changes.
- The `every feature` step of the Windows and macOS jobs no longer runs
  the doc-tests; the three Linux jobs do.
