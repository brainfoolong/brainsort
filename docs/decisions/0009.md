# The website is one complete page per language

## Context

Once the Rust crate had its own benchmark, the website carried it as one
more collapsed section at the end of the C++ page: "The Rust port on plain
vectors", after the harness timing and the C++ API benchmark. A visitor
who came for the crate had to know that the top of the page (the tiles,
the deterministic section, the per-machine timing) described the C++ build
and its opponents, that the Rust numbers were three sections down, and that
the "At a glance" tiles did not include them at all. A visitor who came for
the C++ library saw Rust crates in the summary. Which numbers belonged to
which language was nowhere stated in one place.

The two languages do not have the same kinds of numbers. The deterministic
counts are the same for both: the crate's test suite holds it to every cell
of `results/counts.csv`, and a count of what an algorithm does is the same
in any language. The algorithm-level harness, which times instrumented
ports and upstream code with hardware counters, is C++ code and has no Rust
counterpart. The public call on a plain vector is measured once per
language, each against what its own ecosystem ships.

## Decision

- **Two pages from one generator.** `scripts/website.py` writes
  `site/index.html` (the C++ library) and `site/rust.html` (the Rust crate)
  from one template. Blocks marked `<!--cpp-->` … `<!--/cpp-->` and
  `<!--rust-->` … `<!--/rust-->` are kept on one page and dropped from the
  other; the script gets the page's language as a constant.
- **A switch at the top of both pages** names the language of the page and
  leads to the other, carrying the size, key types, inputs and metric in
  the URL hash. The title, the lead, the stamp and the footer say which
  page it is.
- **The same sections and the same controls on both pages**: Use it, At a
  glance, How to read this page, the size / key type / input panel, What
  each algorithm does, the public call on plain vectors per machine
  (tiles, heat map, tables, all machines side by side, and the C++ / Rust
  pairing on the same machine), Method, All numbers. The deterministic
  section is on both pages and the Rust page says whose numbers they are.
  The harness section exists only on the C++ page, and the Rust page's
  method says why.
- **One renderer for the vector benchmark.** The C++ and the Rust benchmark
  files are loaded into the same shape (brainsort, then the opponents in
  header order, with the index of the like-for-like stable sort), and one
  function renders whichever language the page is. The pairing table has
  the same columns on both pages, C++ first.
- **Every timed number is on the page of the language that was timed.**
  The Rust page carries no harness rows; the C++ page carries no crate
  rows. The pairing table is the one place the languages meet and is
  labelled as such on both pages.

## Consequences

- `scripts/bench.sh`, `scripts/bench.ps1` and the CI website job need no
  change: the script writes `rust.html` next to whatever `--out` names.
- A section that one language lacks is absent from that page rather than
  shown empty; the table of contents differs by that one entry.
- The Rust page repeats the deterministic section rather than linking to it,
  so each page stands on its own and the golden equivalence is stated where
  a Rust reader looks for counts.
