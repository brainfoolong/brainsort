# Variants measured and rejected

Each of these looked right on paper and lost on the hardware counters. They
are recorded so nobody tries them again without a new argument. Times are
from a Ryzen 7 7800X3D at 100,000 elements, GCC 13, `-O2`.

| variant | what was expected | what was measured | verdict |
|---|---|---|---|
| Run-length accumulation in the histogram and scatter loops (keep the bucket counter in a register while consecutive elements hit the same bucket) | fewer store-forwarding stalls | random 0.53 to 0.61 ms, sorted with radix16 0.42 to 0.77 ms: the branch is unpredictable when bucket runs are one or two long | rejected |
| Four interleaved histogram copies, branch-free | no dependency chain on one counter | slower on every input (random 0.500 to 0.554 ms); Zen 4 handles repeated increments of one address well and the extra tables cost more | rejected |
| Fixed-digit histogram first, then re-plan with PEXT if that saves a pass | one pass saved sometimes | never pays: the histogram pass costs about what the scatter pass it saves costs. The varying-bit mask must come from the scout pass, which is why the scout pass was vectorised until it was nearly free | rejected |
| Inlined string compare (overlapping 8-byte loads instead of `memcmp`, four variants including SSE2) | no library call in the inner loop | every variant tripled the branch mispredictions of the scout and of the runs route on keys of mixed length; `memcmp`'s result feeds a conditional move where the inlined code turned the length dispatch into data-dependent branches. Nearly sorted strings 24% slower | rejected, `memcmp` stays |
| Branch-free merge in the runs route (select the next element with masks) | no mispredictions | 2.5x slower on organ-pipe input: the runs this route sees are structured, the branch predicts, and the branchy loop runs ahead of the compare latency | rejected |
| Split at the median also for one- and two-pass plans | half the working set everywhere | the extra pass is not repaid when the radix runs only once or twice: prefixed int32 273 to 382 us, small_range 189 to 217 us | rejected, the gate stays at three passes |
| Partition sort (AVX2 compress-store on two to four distinct keys) for 16-byte elements | the int32 win carried over | two elements per vector: the compress-store passes cost more than the three radix passes they replace (int64 small_range 238 against 208 us); scalar branch-free loops were 2x slower still | 8-byte elements only |
| Two full `memcmp` compares per element in the string scout, byte-loop chunk keys | simplicity | sorted strings 4x slower than timsort. Three-way compares from the shared-prefix offset, load-based chunk keys and lazily computed masks brought random strings from 6.1 to 2.9 ms | replaced |
